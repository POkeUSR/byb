# Crypto Early Movement Scanner V3.0 - Описание Работы Файлов

## Обзор Проекта
Это полнофункциональная система для высокоскоростного сканирования криптовалютных рынков Bybit, предназначенная для институциональных трейдеров. Система обнаруживает переходы от стадии "Накопления" к стадии "Разметки" с использованием передовых количественных индикаторов.

## Архитектура
- **Язык**: Python 3.12
- **Асинхронность**: asyncio для высокой производительности
- **Хранение**: Redis для быстрого доступа к данным
- **Веб-интерфейс**: FastAPI + WebSocket для реал-тайм обновлений
- **Логирование**: Loguru с ротацией и модульной маркировкой

---

## Основные Компоненты

### config.py
**Назначение**: Централизованная конфигурация системы.  
**Функции**:
- Переменные окружения (Redis, Bybit API, Telegram)
- Список символов для сканирования (10 криптовалют)
- Весовые коэффициенты для оценки сигналов
- Настройки логирования с loguru и ротацией файлов
**Как работает**: Загружает .env, экспортирует настроенные логгеры для всего приложения.

### main.py
**Назначение**: Оркестратор всей системы, основной исполнительный файл.  
**Функции**:
- Инициализация компонентов (история, стример, веб-сервер)
- Цикл сканирования (каждые 60 сек): анализ всех символов, расчет оценок, публикация алертов
- Обработка ошибок и graceful shutdown
**Как работает**: Запускает асинхронные задачи, координирует поток данных от WebSocket до дашборда.

### data_stream.py
**Назначение**: WebSocket клиент для Bybit, потоковое получение данных.  
**Функции**:
- Автоподключение и подписка на тикеры, сделки, стаканы заказов
- Обработка сообщений и обновление Redis
- Heartbeat и метрики производительности
**Как работает**: Поддерживает постоянное соединение, парсит JSON, вызывает методы storage для сохранения данных.

### storage.py
**Назначение**: Асинхронный интерфейс к Redis для хранения и извлечения данных.  
**Функции**:
- update_ticker(): Сохранение цен и timestamp
- update_trades(): Объемы и CVD с атомарными обновлениями
- update_orderbook(): Глубины ликвидности
- get_context(): Конвейерная выборка полного состояния
**Как работает**: Использует Redis Pipelines для атомарности, обрабатывает асинхронные операции.

### analytics.py
**Назначение**: Квантовый движок для расчета индикаторов.  
**Функции**:
- calculate_z_score(): Z-score объема для обнаружения аномалий
- detect_squeeze(): Боллинджер Squeeze для сжатия волатильности
- check_absorption(): CVD абсорбция для накопления
- get_relative_strength(): Сравнение с BTC
**Как работает**: Использует numpy/pandas для расчетов, логирует детальные метрики.

### history_loader.py
**Назначение**: Предварительная загрузка исторических данных.  
**Функции**:
- Получение 200 минут OHLCV для всех символов
- Сохранение в Redis для нулевой задержки
**Как работает**: Асинхронная загрузка с ограничением скорости API.

### web_server.py
**Назначение**: FastAPI веб-сервер для дашборда.  
**Функции**:
- Обслуживание index.html
- WebSocket endpoint для реал-тайм обновлений
- Pub/Sub слушатель для алертов
- API эндпоинты для статуса
**Как работает**: Транслирует данные от Redis к браузеру, управляет подключениями клиентов.

### monitor.py
**Назначение**: Мониторинг здоровья системы.  
**Функции**:
- Heartbeat с TTL для процессов
- Метрики производительности
- Получение статуса для дашборда
**Как работает**: Redis-based хранение, асинхронные операции для проверки состояния.

### templates/index.html
**Назначение**: Темный веб-дашборд с реал-тайм данными.  
**Функции**:
- Отображение цен, алертов, статуса системы
- Детальные модалы с разбивкой оценок
- WebSocket клиент для обновлений
**Как работает**: Получает данные от сервера, динамически обновляет UI.

### .env
**Назначение**: Переменные окружения для безопасности.  
**Содержит**: Ключи API, настройки Redis, Telegram токены.  
**Как работает**: Загружается config.py, не коммитится в git.

### requirements.txt
**Назначение**: Зависимости Python.  
**Содержит**: ccxt, redis, fastapi, loguru, numpy, pandas и др.  
**Как работает**: Устанавливается через `pip install -r requirements.txt`.

## Тестовые Файлы

### test_*.py
**Назначение**: Модульные тесты для каждого компонента.  
**Функции**: Проверка логики, mocking внешних зависимостей.  
**Как работает**: unittest с асинхронными тестами, проверка корректности расчетов.

## Процесс Работы

1. **Запуск**: `python main.py` загружает историю, запускает стример и веб-сервер
2. **Поток Данных**: Bybit WebSocket → data_stream.py → storage.py (Redis)
3. **Анализ**: main.py вызывает analytics.py каждые 60 сек для всех символов
4. **Оповещения**: Алерт публикуется в Redis → web_server.py → браузер
5. **Мониторинг**: monitor.py отслеживает здоровье, metrics в дашборде
